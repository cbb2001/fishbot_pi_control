# robot.yaml 参数含义、用法与代码使用位置

审计日期：2026-11-05。配置来源：[config/robot.yaml](config/robot.yaml)。依据是当前工作区源代码，不以 YAML 注释、旧 README 或测试中的同名字符串替代实际调用链。

**结论：不是所有参数都会参与实际运行。** 文件包含当前运行参数、不同入口各自使用的参数、被优先级覆盖的备用值、仅保留校验/历史算法的字段，以及未接入当前实现的开关。是否有效必须结合启动脚本判断；“被读入整个配置或写进 metadata”不等于“影响动作”。

本次仅新增说明文档和审计临时资料，没有修改 `robot.yaml`、控制代码或硬件参数，没有运行实机。

## 1. 覆盖范围与状态定义

共核对 **323 个具体叶子配置项**；将七个舵机的重复字段合并说明后为 **233 类参数**。所有具体项均映射到下文的一条说明；没有重复 YAML 键。舵机具体数值另外列出，未省略不同舵机的配置。

| 状态 | 含义 | 本次参数类别数 |
|---|---|---:|
| 元数据 | 只用于命名、记录、诊断展示或属性保存，不直接改变动作/采集逻辑。 | 5 |
| 条件有效 | 仅特定入口/阶段使用，或是被当前更高优先级配置覆盖的备用值。 | 82 |
| 未发现读取 | 在本仓库生产调用链未找到实际行为消费者；修改不会自动启用所暗示的功能。 | 19 |
| 有效 | 有当前代码消费者；仅在启动相关模块时发挥作用，不代表所有入口都读取。 | 98 |
| 兼容/仅校验 | 当前入口保留加载/范围检查，或历史类仍使用；不驱动当前主要运行逻辑。 | 29 |

“兼容/仅校验”不等于可以直接删除：水下 `UnderwaterConfig.from_robot` 和 `EKFConfig.from_mapping` 会检查必需字段，删掉旧兼容项也可能使程序启动失败。未发现读取项仍可能被整体保存到元数据；本文的判断范围是当前仓库，不包括尚未加入的外部程序。

代码链接中的行号是本次快照，后续编辑会移动；完整路径在链接目标中。下方参数名按完整路径写出，`servo.channels[]` 表示七个舵机列表项中的同名字段。

## 2. 先确定启动入口与配置优先级

| 入口/模式 | 主要读取来源 | 容易混淆的地方 |
|---|---|---|
| `main.py --mode status/observe/record`、`scripts/record_sensors.py` | `runtime`、`sensors`、`logging`，及传感器驱动配置 | main 的 CLI 覆盖 `runtime.mode/mock`；不会因配置导航段而自动开始导航。 |
| `scripts/run_surface_navigation_20261010.py` | `surface_navigation_20261010`、舵机/传感器/安全配置 | 水面会话有自身的传感器配置复制和覆盖；不能把所有水面参数照搬解释成水下行为。 |
| `scripts/run_underwater_navigation_20261026.py` | `underwater_navigation_20261026` + 水面段的尾鳍/几何参数 + 共享采集/PWM/日志设置 | 此版本用估计位置和实时航向控制；当前原入口支持 `(x,y,h,t)` 点表。 |
| `scripts/run_underwater_navigation_20261026_only_one_yaw.py` | 上一行来源，再应用可选 `underwater_navigation_20261026_only_one_yaw` 段及 CLI | 只在水面调向，水下使用锁定误差；**不继承原水下段的 waypoints**，点表须放专用段或 CLI。 |
| `scripts/run_fixed_dive_20260920_100122.py` / `run_fixed_dive_tail_20261009.py` | 共享硬件/采集配置和其 CLI 默认值/选项 | 名为水下导航的 t1–t4 段不会自动成为所有固定下潜脚本的任务参数。 |
| `scripts/train_rl_ppo_20260914.py` | `robot.yaml` 的硬件配置 + 独立 `config/rl_training_20260914.yaml` | RL 的训练、状态、奖励、部分安全/采样配置有独立来源与覆盖顺序。 |
| 旧动作与单设备诊断脚本 | `servo`、两个动作耦合段，或旧 `uart/i2c/depth_sensor` 段 | 有些旧脚本仍读取方向参考角；不能把“当前水下不用”误判为“整个项目不用”。 |

水下两入口的共享来源为：

| 需求 | 应修改的位置 | 优先级/说明 |
|---|---|---|
| IMU/UWB 串口及波特率 | `sensors.imu.*`、`sensors.uwb.*` | 不是旧 `uart.imu_port/uwb_port`。 |

## 3. 需要特别留意的审计结果

### 3.1 未接入、被覆盖与兼容参数

以下是按本次代码审计标记为“未发现读取”的参数，具体依据见逐项表：

- `i2c.pca9685_address`：当前 PCA9685ServoController 仅向 ServoKit 构造器传入 channels，没有传入此地址。修改本项不会改变本仓库 PWM 驱动所打开的设备地址；实际地址取决于所安装 ServoKit 的默认行为。
- `depth_sensor.i2c_write_address_8bit`：当前 Python Linux 驱动使用 7 位地址，没有读取本字段。它可作为 MCU/HAL 地址对照说明，不是本仓库运行时通信参数。勿将 0xEC 填入 sensors.depth.address。
- `depth_sensor.i2c_read_address_8bit`：当前 Python 驱动不读取它；读/写方向由 I²C 库处理，不能靠修改此项更改通信地址。它仅保留地址格式对照意义。
- `uart.uwb_port`：SensorManager 的 UWB 串口来自 sensors.uwb.port；test_uart.py 的端口必须显式传 --port，也不读取本项。当前配置中该值不是正式采集串口的控制来源。
- `uart.imu_port`：正式采集读取 sensors.imu.port；test_uart.py 只打开命令行 --port 指定的端口。修改此项不影响导航或默认采集的 IMU 端口。
- `runtime.offline_recording`：生产 Python 代码未找到按字段读取；离线/脱离终端采集由 start_offline_recording.py 启动独立 record_sensors.py 子进程，与此值无关。整段 metadata 保存不算功能生效。
- `runtime.telemetry_enabled`：生产 Python 代码未找到字段消费；LinkManager 只读独立 link 段心跳配置，当前字段不会开启遥测或改变失联行为。
- `sensors.uwb.optional_underwater`：仅 YAML/DEFAULT_SENSOR_CONFIGS 声明，未找到依此执行的逻辑；水下允许失联由导航状态机决定，通用同步日志仍将无效 UWB 列入 missing_sensors。
- `servo.frequency_hz`：当前驱动创建 ServoKit 时未传入 frequency，也未设置 PWM frequency；改此 YAML 值不改变硬件 PWM 频率。不要与 discrete_executor.command_hz（软件写入频率）混淆。

### 3.3 舵机方向参考角与机械限位不是同一参数

当前 6 号 `top_reference_angle=196` 超出其 `max_angle=176`；5 号 `bottom_reference_angle=0` 小于 `min_angle=2`；7 号 `bottom_reference_angle=180` 大于 `max_angle=178`。这些差异不能仅凭表面数值自动“修正”：不同脚本的解释不同。

- 当前水下/RL 轨迹主要用 `center_angle/min_angle/max_angle` 和耦合标尺，不直接用这些方向端点。
- 旧 `run_action_roll_20260713.py` 等会校验所读取的物理端点是否在机械范围内，当前 6 号上端点会导致对应检查失败。
- `discrete_absolute_actions_20260725.py` 的 `_physical_limit_intersection` 取参考端点与机械限位交集：当前 6 号会收窄为 `[90,176]`，不是现代导航使用的 `[70,176]`。

相应代码见后面的 `direction.top_reference_angle/bottom_reference_angle` 行。这里标记的是静态配置冲突/差异，不代表已经测量了真实机构可动范围。

## 6. only_one_yaw 的实际调参方式

当前 `robot.yaml` **没有** `underwater_navigation_20261026_only_one_yaw` 专用段。无 CLI 覆盖时，新入口复用原水下默认值：`h0=0.5`、`t1=5`、`t2=5`、`t3=60`、`t4=10`，并从水面段继承 `x_d=10/y_d=10/delta_yaw=10` 等参数；自动形成 `(10,10,0.5,NULL)` 单目标。

原水下段的 `waypoints` 即使改成点表，也不会被 only_one_yaw 自动继承。若要在 YAML 配置新版多目标，可增加以下**可选配置示例**（本次没有写回 robot.yaml）：

```yaml
underwater_navigation_20261026_only_one_yaw:
  t3: 180
  t4: 10
  delta_yaw: 10
  waypoints:
    - [10, 10, 0.3, 30]
    - [15, 10, 0.4, 40]
    - [15, 15, 0.3, null]
```

新版每点严格为 `(x,y,h,t)`：`t` 是正秒数或 `NULL`；最后一点/单点必须 `NULL`。数值点在有效 UWB 确认到达或时间到后切换，`NULL` 点持续作为当前目标。目标时间包括调向、上浮和等 UWB；总 t3 不重置。新版 t3 从首次水面调向起计，t4 从每次下潜起计。`t4=t3` 禁止周期上浮，但数值点超时仍可能触发为新目标重新定位的上浮。

CLI 覆盖示例（仅软件模拟）：

```powershell
python scripts/run_underwater_navigation_20261026_only_one_yaw.py --dry-run --t1 0 --t2 1 --t3 15 --t4 3 --waypoint 10 10 0.3 5 --waypoint 15 10 0.4 NULL
```

任意尾鳍/胸鳍参数是否在水下阶段实时更新，应以对应策略为准：新版锁定的是水面剩余 yaw **偏差**，`ki` 非零仍会对该固定偏差积分；EKF 与加速度滤波仍可用于估计和记录，但不再用其水下 XY 或实时 yaw 来切点/重新计算尾鳍目标角差。

更多运行语义见 [only_one_yaw 说明](README_UNDERWATER_NAVIGATION_20261026_ONLY_ONE_YAW.md) 和 [原水下导航说明](README_UNDERWATER_NAVIGATION_20261026.md)。
