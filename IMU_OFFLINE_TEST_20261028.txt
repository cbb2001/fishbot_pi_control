机器鱼 IMU 漂移离线排查流程（2026-10-28）
============================================================
目的：先区分静态偏差和姿态相关误差。此次只做无舵机数据采集。
本流程不修改导航、滤波、UWB 阈值、标定或电机参数。

一、切换局域网前
1. 保存本文件，并把 scripts/analyze_imu_diagnostic_20261028.py 复制到实际运行机器鱼程序的树莓派项目 scripts 目录。
   使用与最近一次实验相同的项目代码和 Python 环境；新增分析器只使用 Python 标准库，不需要联网安装包。
2. 以下命令在树莓派/原来能运行导航程序的终端执行，工作目录为 fishbot_pi_control 项目根目录。
   不要在只有日志、没有实际传感器的 Windows 副本上执行真实采集。
3. 检查命令是否可用（不启动硬件）：
   python scripts/run_underwater_navigation_20261026.py --help
   python scripts/analyze_imu_diagnostic_20261028.py --help
4. 所有采集命令都必须包含 --no-servo；不要加入 --confirm MOVE。
   --no-servo 不初始化 PWM，也不会主动取消其他程序留下的 PWM。
   确保上一次运动程序已停止、舵机已停止，没有其他脚本同时占用传感器/舵机。

二、布置和准备
1. 保持原来的传感器、电源、串口配置和正常供电，让 IMU 通电约 3 分钟，减少刚上电的温度变化。
2. 将机身可靠固定在支架上。支架不能晃动；只用手托着会引入真实加速度。
   可用不同角度的稳定垫块切换姿态。相机、压力、电源等传感器仍按原配置采集，不要临时禁用它们。
   选择与实测温度接近的环境；若在水中，使用可靠固定且能切换姿态的支架，不要让鱼自由漂浮。
3. 初始保持接近水平、鱼头朝池坐标 +X，与正常导航的初始标定约定一致。
4. 可以保持 UWB 开启；本测试不要求收到 UWB。即使显示 UWB=0/4，也能完成无舵机测试。
   终端 XYZ 可能被 UWB 修正，不能用它判断 IMU 是否漂移。
5. 记录供电情况、测试在空气/水中、支架方式、预热时间。建议视频同时拍机身和终端，或口述倒计时。

三、A1：第一遍静止测试
运行：
python scripts/run_underwater_navigation_20261026.py --no-servo --t1 15 --t2 10 --t3 60 --output logs/imu_static_A1

操作：
- 程序启动硬件后，先有 15 秒放置时间，再有 10 秒静止标定时间。
- 最好启动前就固定好，全程不要碰机身、线缆或支架。
- 出现 [diagnostic] 且 t3 接近 60 后，进入正式采集，再保持不动 60 秒。
- 自动结束后检查：reason: time_limit；fault: null；cleanup_errors: []；executor_started: false；alive_workers: []。
- 不应出现 [navigate] 或 [surface]；出现它们说明不是本流程的无舵机运行。
- 若提前停止、标定报错或有 fault，不要将该次数据当作正常测试。保存日志，按第七节处理。

运行离线分析：
python scripts/analyze_imu_diagnostic_20261028.py logs/imu_static_A1 --protocol static

分析器分别取正式采集约 10-30 秒、30-50 秒的两个 20 秒窗口。
每个窗口独立设置 p0=v0=0，重新积分加速度，不使用任何 UWB 位置/速度校正。

四、A2：重复静止测试
保持同一支架、同一朝向，不断电；等 A1 完全结束后运行：
python scripts/run_underwater_navigation_20261026.py --no-servo --t1 15 --t2 10 --t3 60 --output logs/imu_static_A2
python scripts/analyze_imu_diagnostic_20261028.py logs/imu_static_A2 --protocol static

整个过程继续不动。A1/A2 都有偏差：可检查重复性；两次差别大：考虑温度、标定和机身是否真的静止。

五、B1：多姿态测试，正式采集 210 秒
恢复初始水平姿态和 +X 朝向，再运行：
python scripts/run_underwater_navigation_20261026.py --no-servo --t1 15 --t2 10 --t3 210 --output logs/imu_attitude_B1

15 秒放置和 10 秒标定期间必须保持初始姿态不动。
之后看 [diagnostic] 行中的 t3 剩余秒数切换姿态，不要从敲下回车时计时。
每段 30 秒：前 10 秒内缓慢切换并固定，至少后 15 秒完全不动。

正式采集经过时间      终端 t3 剩余时间      姿态
  0-30 秒             210 -> 180           初始水平，鱼头 +X
 30-60 秒             180 -> 150           抬头约 10 度，保持朝向
 60-90 秒             150 -> 120           低头约 10 度，保持朝向
 90-120 秒            120 -> 90            左侧低约 10 度，恢复俯仰接近 0
120-150 秒             90 -> 60            右侧低约 10 度，俯仰接近 0
150-180 秒             60 -> 30            恢复水平，鱼头由 +X 转向 +Y（约 90 度）
180-210 秒             30 -> 0             恢复初始水平姿态和 +X 朝向

角度约 10 度即可，不要求手工精确到 0.1 度；关键是各姿态下可靠固定、稳定保持。
如果一段内没来得及固定、顺序错了或碰到机身，记下当时 t3 值；分析器不会自动识别这种操作错误。
最后一段回到初始姿态，用来检查是否恢复到初始残差水平。

正常自动结束后运行：
python scripts/analyze_imu_diagnostic_20261028.py logs/imu_attitude_B1 --protocol attitude

分析器只取各段最后 15 秒，不积分切换姿态过程。时间零点使用日志 calibration_completed 事件，
它与 diagnostic 倒计时开始基本同时。标签按上述操作时间表赋予，不是自动识别机身姿态。

六、离线看结果，不要现场盲改参数
每个实验目录内会新增 imu_diagnostic_static.txt/.json 或 imu_diagnostic_attitude.txt/.json。
文本输出含义：
- coverage_ok=True：这一窗口采集跨度充分，且相邻记录没有超过 0.05 秒的间隔；不代表物理测试合格。
- raw_linear_acc：扣偏置、转坐标、扣重力后，低通滤波前的加速度。
- filtered_acc：实际参与惯性积分的滤波后加速度。
- mean=(X,Y)、|mean|：水平平均残差及其模长，单位 m/s^2。
- std：样本加速度波动标准差，单位 m/s^2。
- independent integral 的 |p|：该静止窗口从零位置和零速度出发的惯性漂移，单位 m。
- v：同样独立积分得到的末端水平速度，单位 m/s。
- WARNINGS：数据覆盖、时间间隔或运行结束状态的问题。

参考误差预算（并非传感器规格或自动合格判据）：
持续残差 0.005 m/s^2，初速度无误差时，20 秒约造成 1 米漂移。
持续残差 0.020 m/s^2，同样条件下，20 秒约造成 4 米漂移。
姿态测试窗口是 15 秒，不能把它的 |p| 与静止测试 20 秒窗口不加区分地比较。

判断顺序：
1. 先检查测试时机身是否真的不动、coverage_ok 和运行结束状态是否正常。
2. A1/A2 的静止残差持续偏大：重点查静态标定、预热、温度、固定方式。
3. 初始水平正常，倾斜后残差明显变大，回水平又恢复：重点查姿态/轴向/重力补偿。
4. 回初始姿态后仍与起始明显不同：可能有温漂、标定漂移或固定姿态未恢复，先重复确认。
5. 所有固定姿态都正常：再安排固定机身的单尾鳍、单侧鳍、组合动作测试。
   当前导航入口没有独立的单鳍测试参数，本次不通过随意修改 PI 增益或加入 --confirm MOVE 来替代。
   固定姿态测试通过也不能证明动态惯性导航准确。
6. 不要现场把 Y 加速度统一减去 0.08，不要随意修改 yaw_sign、auto_bias 或把水下速度逐帧清零。

七、异常与重跑
- 输出目录已存在：改新目录名，例如 logs/imu_static_A3 或 logs/imu_attitude_B2；不要删除/覆盖原始日志。
- 校准 coverage/count/gap invalid：先检查对应 IMU/压力传感器采集，保存完整报错和目录。
- 静止性/角度波动校准失败：确认支架固定、线缆不拉扯；恢复初始姿态后用新目录重跑。
- 串口/I2C/相机无法打开：检查是否有别的采集程序占用；沿用上次正常实验的环境和权限。
- fault 非空或 cleanup_errors 非空：记录完整文字；不能仅因存在数据文件就判定采集正常。
- 需要提前结束：按一次 Ctrl+C，等程序清理并返回终端；提前结束不是正常 time_limit，末段数据可能不足。
- 分析报缺文件：核对目录、是否已结束、是否完成标定，不要改原始 JSONL。
- 切换局域网可能让 SSH 断开：先完成切网和重新连接，再启动测试；运行期间保持连接到树莓派。

八、回来后保留和带回的内容
完整保存以下三个目录（不要只保存截图或挑选部分 IMU 数据）：
logs/imu_static_A1
logs/imu_static_A2
logs/imu_attitude_B1

每个目录包括 metadata.yaml、calibration.json、result.json、events.jsonl、imu_filtered.jsonl、
raw_imu.jsonl、raw_depth.jsonl、raw_uwb.jsonl 等原始文件，以及新增分析报告。
另记录：各姿态实际方向、角度、是否晃动/碰触、发生时的 t3 值、测试环境和预热时间。
如有视频，保留视频。每次运行前确认磁盘空间充足，当前配置会保存相机图片。

此次核心流程约 8 分钟采集（不含预热、操作、分析）。完成这三次即可，
先取得可重复的静止/多姿态证据，再决定如何改补偿和水下转向逻辑。
