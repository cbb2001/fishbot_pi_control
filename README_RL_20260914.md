# 侧鳍在线 PPO（20260914）

当前入口只控制侧鳍四个舵机（4、5、6、7），尾部舵机（1、2、3）不会写入动作命令。旧 main.py 和 20260725 人工动作流程保持不变。

20260919 更新：`action2(theta,t,b1,b2)` 的 theta 为 **[-53,0,53]**，t 为 **[0.3,0.6] 秒**，模式 `(b1,b2)` 为 `(0,0)、(1,-1)、(1,1)`，共 **18 个基础动作**。b1=0 时 b2 归一化为 0。动作表固定在 `control/runtime/rl_actions_20260914.py`，两份 YAML 共用此定义。

连续动作遵循两条硬约束：

1. 首个动作 b1=0，随后必须 0、1、0、1 交替，包括 theta 不变的动作。
2. 仅在 b1=1 且 theta 与上个已完成动作不同的时候记录方向：`direction=sign(theta-previous_theta)*b2`，+1 表示前进，-1 表示后退。首次有效方向自由选择，后续有效方向必须相反。b1=0 或 theta 不变时不刷新上次有效方向；中间相隔多少动作都保留记录。中心角固定，比较“4号中心角+theta”等价于比较 theta。

例如 `(-53,.3,0,0) → (53,.3,1,1)[前进] → (53,.6,0,0) → (-53,.6,1,1)[后退]` 是合法序列：这里 b2 都是 +1，但根部运动方向相反。相同的 b2 不必交替，必须交替的是上述方向分类。

策略网络用一个 18 分类联合输出头，按当前约束状态屏蔽非法动作，再进行采样；不在采样后改写动作。b1=0 阶段有 6 个合法选择；b1=1、尚无方向记录时有 12 个，已有方向记录时有 8 个。rollout 保存每条样本的掩码，PPO 更新时用同一掩码重算 log probability、entropy 和概率比。执行器在动作启动前再次校验规则，仅在终点 PWM 写入成功后推进序列状态。

规则不会造成无动作可选，但允许 b1=1 且 theta 不变的空行程。这时尖端幅度为零，b2 两个值暂仍保留，不计入方向交替。这里的“前进/后退”是按指令定义的分类，不是实测鱼体运动；交替也可能使推力抵消，不能保证下潜或净推进改善，应根据新实物日志判断。

根部仍以五次平滑插值从上个目标角运动至 `center4+theta`；b1=1 时尖端在 t/2 到达 `center5+b2*abs(theta-previous_theta)/106*90`，t 时回中（106 和 90 可被 robot.yaml 的耦合标定覆盖）。b1=0 时尖端保持中位。6/7号按各自中心镜像4/5号，不改变原有左右联动定义。

当前两份 YAML 均设为每收集 8 条已完成且有动作后观测的样本，冻结 rollout 在后台更新 PPO。更新期间不提交新动作，舵机保持最后动作的终点角度；传感器和安全检查继续运行。更新完成后重新读取状态再选动作。8 条样本仍属小批量，稳定后可比较 16 条。由 training.update_every_actions 控制。

历史窗口与更新间隔独立。Fin 输入为 `15+history_length×5+3` 维，末尾新增 `[previous_theta/53,next_b1,last_effective_direction]`，使 actor 和 critic 知道当前交替阶段。两份 YAML 当前均为 history=12（78维）。这3维约束状态独立保留，不会因历史窗口滑动而丢失。每8条更新不要求历史改成8；history可单独比较8/12/16，改输入维度后应新开实验。

序列状态和历史跨 PPO 更新、episode 连续保留，所以更新间隔为奇数5也不会破坏 b1 交替。网络更新期间保持最后动作终点，完成后用最新可用传感器状态及当前序列状态生成下一动作。只有新进程启动、自动标定并回中后才从 previous_theta=0、next_b1=0、无有效方向重新开始。动作中途被取消后不允许直接接着执行新动作，应退出并重新启动回中，避免半个行程被当作完整动作。

**旧 132/220 动作 checkpoint 不兼容，首次使用新版不要带 `--resume`。** 新检查点格式为 `fin_only_v3`，保存动作表、规则版本和输入定义；旧格式会在启动传感器/舵机前被拒绝。以后同版本、同网络配置可以恢复权重和优化器，但每次启动仍重新标定、回中并重置执行序列和历史，不恢复水下旧姿态。

`commands.jsonl` 新增 `action_index`（0～17）、`action_mask`、`sequence_before` 和 `effective_direction`（+1前进/-1后退/0不记录）；完成后的状态见 `events.jsonl` 中的 `fin_action_completed`，实时状态见 `fin_sequence`。命令提交日志不代表动作已经完成，应与完成事件一起核对。

episode 由 training.episode_duration_s 墙钟上限决定，包含动作执行和 PPO 等待。启用 success_enabled 时，深度和 yaw 同时进入容差并连续 success_hold_s 秒，且满足 min_episode_s、min_actions，就提前以 success 结束。越界或传感器断档会重置连续达标计时，yaw 使用 ±180 度环绕误差。时间结束是 truncated，达标是 terminated。

当前配套参数：update_every_actions=8、min_transitions_per_update=8、minibatch_size=8、update_epochs=3、learning_rate=0.0001。同一批8条样本最多优化3步。正式配置当前把target_kl注释掉，未启用KL提前停止；短时配置启用target_kl=0.03，KL超限会提前结束本轮优化，随后继续训练。正式配置每episode60秒、最多5个、总训练上限300秒；短时配置每episode10秒、最多2个、总上限20秒。实物稳定后比较16条更新；update_timeout_s 应结合树莓派实测耗时设置。若单次更新超时，先减小网络或update_epochs；增大更新间隔主要降低暂停频率，不保证单次更新更快。depth_tolerance/yaw_tolerance 用于episode结束，reward的scale参数独立。修改网络、动作、history或PPO参数后不要直接恢复旧checkpoint。

dry-run 命令：
E:/anaconda3/envs/fishbot-analysis/python.exe scripts/train_rl_ppo_20260914.py --rl-config config/rl_training_20260914.yaml --config config/robot.yaml --h0 0.5 --theta0 0 --dry-run --max-episodes 1

真实设备必须提供 --confirm MOVE。日志写入 logs/rl_20260914/<session>_fin_only/。mock 传感器不模拟动作对鱼体的水动力影响，dry-run 只能验证程序闭环，不能证明真实定深收敛。

## 启动、固定压力参考与IMU自动标定

启动顺序：加载/检查配置 → 启动 IMU、压力、电源采样与健康监测 → 等待 pretrain_wait_s（主配置20秒、试运行30秒）、预热5秒 → 用5秒稳定窗口只标定 IMU 姿态与去重力参数 → 初始化侧鳍并写入中心角、等待稳定 → 构建状态并开始动作。IMU 标定未通过不会初始化舵机。初始回中是写入中心角后等待，并没有未知初始姿态的角度反馈，不能称作可验证的平滑启动。

每次启动（含 --resume）只重新采集 IMU 姿态零点，episode 之间不重复标定。压力自动标定已取消，固定参考值只在 `--config` 指向的机器人配置中设置，默认文件为 `config/robot.yaml`：

```yaml
depth_sensor:
  surface_pressure_mbar: 1038.131 # mbar；内部乘100得到103813.1Pa
```

以后修改压力参考只改这一处，两份 RL 配置共用它。启动压力样本不会覆盖该值，也不再要求压力标定窗口的样本数和标准差；IMU 仍需保持静止通过标定。深度按 `h=(pressure_pa-103813.1)/(water_density_kg_m3*gravity_mps2)` 计算，状态、奖励、episode 达标和深度保护共用该深度。压力采样及无效数据检查继续工作；yaw=0 仍表示本次初始朝向。

`calibration_20260914.json` 保存 IMU 样本数量、姿态零点与去重力检查结果，以及 `pressure_reference_mode: fixed_config`、`surface_pressure_mbar` 和 `p_surface_pa`；压力标定样本数为0、标准差为null。`depth_calibrated: true` 在此表示固定参考已就绪，并非做过压力自动标定。`metadata.yaml` 保存包含固定压力参考的机器人配置与实际保护阈值。启动期间仍保存原始压力采样。

## 故障停止与保护参数

新增 `rl_safety_20260914.py` 独立线程，覆盖等待、标定、动作执行、策略推理、PPO 更新和正常退出回中阶段。关键传感器缺失、无效、工作线程异常以及电压/电流/深度越界会触发停止。数据超时/状态停更的年龄拦截由 `state.enforce_data_freshness` 控制（见下文）；两份现用 RL YAML 均已关闭。旧人工控制配置中的 `stop_on_imu_timeout` 不决定 RL 的年龄拦截。

| 参数 | 来源与默认值 | 作用 |
| --- | --- | --- |
| min_voltage_v | robot.yaml：10.5 V | 低于阈值停止 |
| max_current_a | robot.yaml：10 A | 电流绝对值超过阈值停止 |
| max_depth_m | robot.yaml：5 m | 按配置固定参考换算的深度超过阈值停止 |
| state.sensor_age.*.fault_ms | RL YAML：IMU 100、压力 300、电源 2000 ms | 总开关 true 时过期停车，false 时仅记录年龄告警 |
| state.max_state_age_ms | 150 ms | 总开关 true 时检查状态/决策年龄，false 时仅记录年龄告警 |
| runtime.safety_poll_interval_s | 0.01 s | 监测线程检查周期 |
| runtime.update_timeout_s | 2 s | 网络更新超过时限取消并停止 |

可在 RL YAML 的 `safety` 字典覆盖三个物理阈值，无需修改旧人工控制配置。应按电池、测量量程和水池实际范围设置，目标深度需小于允许深度，5 m 的原默认值不是当前试验环境的推荐值。阈值目前采用单次越界触发，无去抖延迟。

**故障或人工停止**：取消排队动作，不继续摆动，也不再尝试回中，由执行器自身线程逐通道关闭侧鳍 PWM；即使指定 `--keep-pwm` 也不能绕过故障停车。一个通道关闭失败会继续尝试其余通道，失败写入日志。关闭 PWM 表示停止主动驱动，不等于锁住机械姿态或自动上浮。

**正常结束**：从最后已知命令角平滑回中，然后默认关闭侧鳍 PWM；`--keep-pwm` 只在没有故障的正常结束时保留回中后的 PWM。清理步骤独立处理，即使某线程退出报错，仍继续停止其他组件。`faults_20260914.jsonl`、`fault_summary_20260914.json` 和实时状态文件记录故障与清理错误。

Ctrl+C 或 `kill -TERM <训练PID>` 会触发上述人工停止流程。不要用 `kill -9` 作为软件停车方式：它绕过清理，PWM 控制器可能保留最后输出。此保护仍是 Linux/Python 软件监测，采样周期、线程调度和总线阻塞决定实际响应；电源默认仅 2 Hz，10 ms 检查不能捕捉采样间隔内全部电流尖峰，也无法保证进程崩溃或 I2C 卡死时成功关闭输出。

## 数据超时总开关

两份 RL YAML 已按实物调试要求设为 `state.enforce_data_freshness: false`。关闭后，IMU、压力、电源样本年龄、RL 状态年龄、策略决策依据年龄以及标定窗口末样本年龄，不再因超过原阈值而停止或拒绝样本。同步器和状态构建器同步采用此设置，继续使用最近可用且有效的读数，保留真实时间戳，不伪造新采样。缺省未写该参数的旧配置仍按 `true` 处理。

`sensor_age.*.warn_ms/fault_ms` 与 `max_state_age_ms` 保留作诊断和恢复拦截用；总开关为 `false` 时不会因为这些上限停车。`rl_state_20260914.jsonl` 记录传感器年龄和告警，实时状态另有 `data_freshness_enforced`、`latest_data_age_ms`、`data_age_warnings`；旧决策继续执行的告警写入 `events.jsonl`。总开关 `false` 优先于下述 `stop_on_stale_decision`。

这不会关闭缺失数据、非有限值、解码/设备错误、未来时间戳、线程异常、电压/电流/深度越界等检查。若传感器停止更新但最后读数有效，程序会继续使用旧值，越界监测也只能依据旧值，不能保证及时发现新的物理变化。IMU 标定仍须满足窗口覆盖、样本数和稳定性要求；压力不参加标定。达标判定仍要求连续的新样本，过期或重复读数不会制造“持续达标”，这项检查只影响能否判成功，不会因超时触发故障。

训练时限、动作执行/网络更新超时、首次样本等待、标定总等待和线程清理超时继续保留；它们不属于运行中数据年龄阈值。关闭状态年龄拦截后，若始终等不到动作终点之后的状态，到训练时限时会记录 `transition_discarded_no_post_action_state` 并结束，缺少后续观测的动作不伪造训练样本。

## 决策过期拦截开关

`state.stop_on_stale_decision` 控制 `DECISION_STALE`：默认 `true`，策略决策依据的状态年龄超过 `state.max_state_age_ms` 时停止。设为 `false` 后，允许继续使用该决策，并在 `events.jsonl` 写入 `stale_decision_allowed`，记录状态时间戳、决策年龄和策略版本。该记录表示允许过期决策，不保证之后一定提交动作；达标或其他故障仍可阻止动作。

`config/rl_trial_10s_20260914.yaml` 中本项为 `false`，常规配置本项为 `true`；但当前两份配置的数据超时总开关均为 `false`，所以均不会拦截旧决策。若以后恢复 `enforce_data_freshness: true`，本项才单独决定是否拦截决策年龄。修改时需要一起更新相关 Python 代码，仅上传 YAML 到旧代码不会生效。关闭拦截允许较旧观测产生的动作继续执行，并不消除原来的偶发延迟。
